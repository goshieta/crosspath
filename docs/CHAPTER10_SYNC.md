# 第10章：差分・階層同期の実装と試験

対象は詳細設計書 v0.8 の第10章です。同期方式の提案資料は参考モデルとして読み、
24bit ID空間、ID0予約、4Bレコード、保存後ACKなどはアプリ詳細設計を適用しています。
実BLEの性能・大規模収束率をシミュレーションの数値から保証するものではありません。

## 検証画面

通常画面上部の「BLE検証画面を開く」から使用します。両端末を新しいAPKへ更新してください。

- FULL：従来の全件交換。従来のMTU23・保存後ACK待機の試験を保持。
- FLAT：SHA-256のSUMMARYが一致すればDATAなし。不一致なら256 ID以下のID_LISTを交換し、
  不足IDをREQUESTして、その人物のDATAだけを交換。
- HIERARCHICAL（初期選択）：L1／L1'ページ、必要なL2 bitmap、不足人物DATAを交換。
  双方が対応する場合はこちらを優先し、片方がFLATのみならFLATで合意。
  差分方式からFULLへ無条件にフォールバックしません。

差分・階層同期では共有ATT換算予算（初期値65536B）と接触時間（初期値45秒）を指定できます。
1〜45秒で3秒・10秒条件も設定可能です。値は実測調整用の入力であり、3MbpsやC=55500を前提としません。
FULLにはこの2入力を適用せず、従来の片方向15秒・全体45秒を使用します。
GATT接続の初期化を含む通信層の45秒上限も残るため、同期開始から45秒を使い切れるとは限りません。

差分・階層同期も検証画面の手動開始です。完了後の自動再探索、通常画面・バックグラウンドへの
継続通信接続は今回の範囲外です。画面を離れると停止します。

## 比較と転送

ID空間は全16384ブロック、1ブロック1024 ID。ブロック0だけはID0を除く1023件が満杯です。

- L1_PAGEは連続256ブロック、全64ページ。各ページで固定長L1とL1'の短い方を選択。
- L1'は上位bitから00=空、01=満杯、10=部分。予約11、端数bit、部分の件数不整合を拒否。
- 部分ブロックは同件数でもL2照合。bitmapは128B、offset0が先頭byteのMSB。
  範囲・snapshotToken・popcount・予約ID0を検証。
- 相手が空ならL2なしで自分の全ID、相手が満杯なら送信なし。
  相手が部分なら「自分のbitmap AND NOT 相手のbitmap」のみ送信。
- 候補ブロックは相手の件数が少ない順。同順位は接触ごとにシャッフル。
- 最大256件、同一ブロック内のID昇順でDATAを生成。保存後ACKが確定してから方向を交代。
  一方の送信が終了したら、他方は残り予算を使用可能。
- 送信済みIDをACK後に候補から除外。ACK喪失は同一バッチを最大2回再送し、受信側はDBを再照会。
- 受信側も受信IDが自分の開始時スナップショットにないことと、完了時の不足件数を検証。
  L2で照合した部分ブロックは不足ID集合そのものも検証。

完了表示は、開始時のID集合に差がなければEQUAL、不足分を保存して双方向の検証が完了すればEXCHANGED。
途中切断、制御ページ不足、CRCエラー、容量拒否、時間・バイト予算切れでは完了扱いにしません。
地点は集合比較・digestに含めず、同一IDの異なる地点は再送で上書きしません。
接触途中で追加されたIDは現在のスナップショットに混ぜず、次回に回します。

## Roomとキャッシュ

`SafetyRepository.syncSummary`がsessionId・revision・16384件のブロックカウントを
同一の短いトランザクションで取得します。Application起動後、有効な期間があればカウントを準備。
カウントは挿入トランザクションの成功する経路で更新し、DBとのrevision不一致時は再構築します。
ロールバック後に不整合なカウントを利用しません。

L2はsessionId／revision／block単位の最大128エントリのLRUキャッシュ。
DATAの取得は最大256 ID、bitmapの取得は1ブロックまで。全人物をJavaのList／Mapへ展開しません。
FLATのID集合は上限が固定されたBitSetで扱い、受信ページも256 ID以下です。
両モードとも検証用BitSetを含め、保持量は24bit空間に基づく固定上限です。

FLATのSHA-256は256件ずつ短いDBトランザクションで読み出して計算し、期間・revision・件数でキャッシュ。
変更なしの再接触で全件を再走査しません。HIERARCHICALは全ID SHA-256の計算を必須としません。
新しい期間・期限終了で同期キャッシュを破棄し、古いスナップショットの読取りを拒否します。

## この実装内の暫定通信プロファイル

詳細設計で未割当の値・終端手順は以下に固定しています。別実装との合意済みではありません。

|項目|値／規則|
|---|---|
|mode|FULL=1、FLAT=2、HIERARCHICAL=3|
|capabilities|FULL=1、保存後ACK=2、FLAT=4、HIERARCHICAL=8|
|HELLO|major=4、minor=0、masterVersion=0x20260926。差分方式はmaxBody>=525を要求|
|BEGIN|両端末が自身のsnapshotTokenを送信してから制御ページを交換|
|L1_PAGE|各ページのstartBlockは0,256,…,16128の順。64ページと総件数の検証が必須|
|ID_LIST|pageNoは0開始、IDはページをまたいで厳密昇順。最終ページはisLast=1、空の終端ページも許可|
|REQUEST|要求先のsnapshotToken、requestIdは1開始、最大256 ID。件数0のREQUESTで要求一覧を終了|
|FLAT比較|一覧全体をbounded BitSetへ蓄積してSHAを確認後、不足REQUESTを交換。ページ到着時の先行要求は行わない|
|TURN_END|0=この方向の完了、1=PARTIAL、2=ACK後の方向交代。2は差分方式専用|
|DONE|0=EQUAL、2=EXCHANGED。Clientが開始しServerが確認を返す。異常時は成功DONEなしで切断|
|idDigest|ASCII `crosspath/id-set/v1` + NUL、major 1B、masterVersion 4B、personCount 4B、昇順ID 3B列のSHA-256。整数はBig Endian|

各本文末尾のCRC32と10Bフラグメントヘッダーは従来どおりです。
HIERARCHICALとFLATで同じDATA／保存後ACKを使います。

## 予算・統計・再接続抑制

初期の送信予算を50/50に配分し、片方の方向が終了した場合は未使用分を他方へ渡します。
制御、CRC、再送、フラグメントヘッダーを含め、メッセージをキューへ入れる前に予算を予約します。
未送信の途中メッセージにも予約が残るため、切断時の予約額は実際の発行量と一致するとは限りません。

画面のATT換算TX/RXは、GATTへ発行した／受け取ったフラグメント長に、ATT opcode・handleと
Write応答／Indication確認相当の4Bを加算します。部分受信も通信層で計上します。
無線層の再送、暗号化、接続確立・サービス探索等を含む電波上の総バイトではありません。
有効レコード率=ACKで確認できた相手の新規保存数／送信試行レコード数、
ATT効率=同新規保存数×4／ATT換算TX。DATA 0件時はN/Aです。
ACK喪失後の再送ACKが既知を返した場合、初回の新規保存は送信側で確認できないため、
新規保存数は過小計上される場合があります。受信側の新規受信件数は別に表示します。

再接続抑制はApplication寿命内で最大256相手を保持し、再起動・新期間で破棄。
同じ期間のpeerTokenを再利用し、照合したローカルrevisionと、FLATの場合はID集合digestも記録します。
HIERARCHICALは全ID SHAを強制しないため、抑制キーにローカルrevisionを使い、件数から集合一致を推測しません。
成功は60秒、失敗は5・10・20・40…最大300秒、±20%ジッター（300秒を上限）。
ローカルrevisionが増えたときは既存抑制を最長5秒まで短縮します。
抑制は自分から接続する際に適用し、新しい情報を持つ可能性がある相手からの接続は拒否しません。

Kは初期値0＝未設定。検証済みかつ新規受信なしのEQUALだけを診断カウンターへ反映し、
同じ相手との連続接触は加算しません。新規受信・未完了接触でリセットします。
Kを設定した場合でも推定収束は診断値のみで、探索・中継を永久停止させません。
エリアの所属は推測せずUNKNOWNとして同じ手順を使います。世界全体のcoverageは算出しません。

  11:14:58.586に接続開始、11:15:43.591に接続時間枠終了。

  受信完了60ページの段階で終了し、L2／DATAには未到達。

  データ保持で更新し、MainActivityの起動 `Status: ok` と起動プロセスのクラッシュログなしを確認。

両端末を更新し、HIERARCHICAL・予算65536B・45秒・ACK待機OFFで開始してください。
両側に同じ3件が残っていれば「階層同期完了 / EQUAL（不足なし）」「DATA送信=0件」が期待値です。
期間満了でデータが消えた場合は、実際の登録状態に合わせて試験条件を作り直します。
再接触は成功時の抑制（最大72秒）を待ちます。FLAT・MTU23でも繰り返せます。
小さな集合では階層要約の方がFULLより多くなることがあるため、通信量の比較は件数と分布も記録します。
大規模性能、3秒・10秒の実BLE速度と双方保存人数、複数機種での交互転送は未測定です。
