# crosspath デモ実行ガイド

crosspath は、災害時に携帯電話網が利用できない状況を想定し、Bluetooth によるすれ違い通信で安否情報を共有することを目指した Android アプリです。

現在は開発中で、公開デモURLやストア配信はありません。配布されたソースコードをPCで開き、Android エミュレーターまたは Android 端末にインストールしてお試しください。ブラウザや iPhone では実行できません。

## 今回体験できること

- デモ用IDによる初回登録と、個人IDの表示・コピー・共有
- 通知対象者の登録・削除
- 九州の県・市町村を選択する生存登録の操作
- 72時間のカウントダウンと、緊急時画面への切り替え
- 通知対象者の受信状態を表示する画面と、端末内へのデータ保存

**Bluetooth による端末間通信、バックグラウンド通信サービス、サーバーでの本人登録・ID発行は未実装です。** 2台の端末で起動しても安否情報は送受信されません。本デモは画面とローカル保存の確認用で、実際の災害時の安否確認には利用できません。

## 1. 必要な環境

| 項目 | 必要なもの |
|---|---|
| PC | Android Studio を実行できる Windows / macOS / Linux |
| 開発環境 | このプロジェクトの Android Gradle Plugin（AGP）9.4.1 / Gradle 9.6.0 に対応する Android Studio |
| Android SDK | SDK Platform 37（ビルド用）、SDK Platform-Tools。エミュレーター利用時は Android Emulator とシステムイメージも必要 |
| Java | JDK 25（同梱の Gradle Daemon 設定で指定。Javaソース互換性は11） |
| 実行先 | Android 12（API 31）以上のエミュレーター、または Android 端末1台 |
| ネット接続 | 開発環境の準備と、初回ビルド時の依存ライブラリ取得に必要 |

デモの初回登録にアカウント、APIキー、外部サーバーの設定は必要ありません。

## 2. ソースコードを開く

1. 共有されたソースコード一式をダウンロードします。ZIPの場合は先に展開してください。
2. Android Studio を起動し、**Open**（または **File → Open**）を選びます。
3. `settings.gradle.kts`、`gradlew`、`app` フォルダーが入っているプロジェクトのルートフォルダーを開きます。
4. SDK Manager で Android SDK Platform 37 と必要なSDKツールをインストールします。
5. Gradle の同期が完了するまで待ちます。JDKの設定を求められた場合は JDK 25 を用意し、Gradle用のJDKとして設定します。

初回は Gradle・ライブラリ・JDKなどのダウンロードに時間がかかる場合があります。

## 3. アプリを起動する

### 方法A：PC上のエミュレーターで体験する

1. Android Studio の **Device Manager** から仮想端末を作成します。
2. Android 12（API 31）以上のシステムイメージを選び、必要に応じてダウンロードします。
3. 仮想端末を起動します。
4. **Build Variants** で `app` のビルドバリアントを **debug** にします。
5. 実行対象に仮想端末を選び、`app` の **Run（▶）** を押します。

### 方法B：Android の実機で体験する

1. 端末の設定で開発者向けオプションと **USBデバッグ** を有効にします。
2. PCと端末をデータ通信対応のUSBケーブルで接続し、端末側でデバッグ接続を許可します。
3. Android Studio の実行対象にその端末を選びます。
4. **Build Variants** で `app` を **debug** にして、`app` の **Run（▶）** を押します。

デモ用IDを入力できるのは debug 版です。release 版はサーバー登録が未接続のため、今回の体験には使用しません。

## 4. 操作を試す

### 初回登録

1. 名前に `デモ利用者` を入力します。
2. 「デモ専用ID」に `1001` を入力します。
3. 「登録する」を押し、登録結果に表示される個人IDを確認して、ホームへ進みます。

デモ専用IDは `1〜16777215` の整数です。複数端末で画面を確認する場合は、`1001`、`1002` のように端末ごとに異なる値を使用してください。IDはサーバー発行ではなく、入力した値が端末内に保存されます。

### 通知対象者を登録する

1. 下部の「通知対象者」タブを開きます。
2. 対象者の個人IDに `1002`、名前に `デモ対象者` を入力します。
3. 「登録」を押して一覧への追加を確認します。削除の操作も試せます。

この例では2台目の端末は必要ありません。

### 生存登録と緊急時画面を確認する

1. 「ホーム」タブへ戻り、「生存登録」を押します。
2. 九州の県と市町村を選び、「確定」を押します。
3. 緊急時画面に切り替わり、72時間のカウントダウンとダーク表示が始まることを確認します。
4. 下部タブで通知対象者や通知画面に移動し、ホームに戻ると緊急時画面が表示されることを確認します。

通信機能が未接続のため、通信できない旨の表示は想定された動作です。カウントダウンの開始は実際の送受信開始を意味しません。対象者の受信状態「ー」は未受信を示し、この手順だけで「〇」や安否受信の通知が発生することはありません。

### 保存状態を確認する・最初からやり直す

アプリを終了して開き直すと、登録情報や通知対象者、開始した期間の状態が引き継がれます。

初回登録からやり直す場合は、Android の設定からこのデモアプリのストレージにある「データを消去」（機種により名称が異なります）を実行して、再度起動してください。**デモアプリ内の登録情報・通知対象者・期間などの保存データは削除されます。**

## 5. コマンドでビルドする場合（任意）

Android Studio の Run を使用する場合、この操作は不要です。以下はJDKとAndroid SDKを設定済みの方向けです。プロジェクトのルートフォルダーで実行してください。

SDKの場所は Android Studio が生成する `local.properties` の `sdk.dir`、または環境変数 `ANDROID_HOME` で指定し、`JAVA_HOME` は使用するJDKのフォルダーに設定します。他のPCのパスが記載された `local.properties` はそのまま使用しないでください。

Windows（PowerShell）：

```powershell
.\gradlew.bat :app:assembleDebug --console=plain
```

macOS / Linux：

```bash
sh ./gradlew :app:assembleDebug --console=plain
```

成功すると `app/build/outputs/apk/debug/app-debug.apk` が生成されます。SDK Platform-Tools の `adb` がPATHに登録され、端末またはエミュレーターが接続されている場合は、次のコマンドでもインストールできます。

```bash
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

インストール後は端末のアプリ一覧から起動します。debug版のアプリIDは `com.example.crosspath.debug` です。

## 6. 困ったとき

| 状況 | 確認すること |
|---|---|
| Gradleの同期・ビルドが失敗する | エラーの先頭を確認し、AGP 9.4.1対応のAndroid Studio、JDK 25、SDK Platform 37が用意されているか確認してください。初回の取得にはネット接続が必要です。 |
| SDKの場所が見つからない | SDK Managerでインストール先を確認し、`local.properties` または `ANDROID_HOME` をそのPCのパスに設定してください。 |
| 実機が一覧に出ない | USBデバッグ、端末側の接続許可、USBケーブルを確認してください。Windowsでは端末用USBドライバーが必要な場合があります。 |
| デモ専用IDの入力欄がない・登録できない | debug版を使用しているか、名前が空でないか、IDが指定範囲の整数か確認してください。 |
| 初回登録の画面が出ない | 登録済みの情報が端末内に残っています。やり直す場合は前述のデータ消去を行ってください。 |
| 通信できない・対象者が未受信のまま | 今回のソースではBluetooth通信が未実装のため、想定された動作です。 |

技術的な構成は [開発者向けREADME](README.md)、実装範囲の詳細は [設計照合記録](docs/remaining-features.md) を参照してください。
